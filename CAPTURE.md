# Capture decisions and limits

- Capture starts when Debrief is first selected, then continues while another DevTools panel is visible. Recent HAR entries are imported if available; unavailable historical bodies are labeled. Reload manually for requests missed before DevTools opened. HTTP requests appear when completed, so pending requests and ongoing streams will be absent.
- **HTTP only is off by default.** Selecting Debrief starts network capture and the page probe. Enabling HTTP-only detaches the probe and stops page sampling. Turning page context on/off clears the previous capture and invalidates outstanding samples. Mode selection is in-memory for this DevTools session and persists across navigation in the same tab; a new DevTools session starts with page context enabled again. HTTP-only still captures potentially sensitive HTTP headers and bodies.
- Keep the latest **150 requests** and **100 errors** in memory. The UI may retain one selected request after it leaves that buffer so active inspection is not interrupted. Clear and navigation discard the selection too; Pause stops new captures and detaches the probe. No captured data is written to disk. Closing DevTools destroys extension memory. The page's small error buffer is drained every second; unload attempts cleanup and a **4-second inactivity lease** removes it if unload is missed (when the page event loop can run).
- Auth and Pusher are sampled every second; each request uses the most recent sample at completion. The timestamp is in the Markdown. Historical requests have no auth snapshot. Auth covers up to 20 matching keys per storage area among its first 300 keys (`auth`, `token`, `jwt`, `session`, `credential`, `api key`, `secret`, `pusher`), plus readable cookies. Arbitrary storage is intentionally not dumped.
- Nearby errors span **5 seconds before request start through 5 seconds after completion**, limited to 20. Copying immediately cannot include errors that have not happened or been polled yet. Temporal proximity does not imply causality. Open DevTools before reproducing; early startup errors before probe attachment are missed. Pre-cached `console.error` references and later console replacements may bypass capture.
- Pusher checks `window.Pusher.instances`, `window.pusher`, and `window.Echo.connector.pusher`. It reads state, channel names and subscription flags without calling connect/subscribe/send or wrapping WebSocket. Only exposed instances are visible; no channel members, socket IDs or frames are collected. Channel names pass through text redaction, including common user/account identifier patterns.
- Retain text bodies up to **256 Ki characters** (also skip known response sizes over 256 KiB). Body output is limited to **12,000 characters**; other sections to **6,000**, keeping an 80% head and 20% tail with an omission marker. All redaction happens before output truncation. Binary, unsupported encodings, oversized bodies and unsafe-to-parse JSON are explicitly omitted. Raw copy bypasses redaction, **not capture/output limits**.
- Redaction is intentionally conservative. It removes credential headers, cookies, sensitive/PII fields, URL userinfo, emails, common phones/IPs/cards/IDs, JWTs, private keys, common API keys and long opaque values, including percent-encoded forms and known-secret echoes. It can hide useful hashes/names and cannot recognize every personal fact in arbitrary prose or unknown encodings. Review the preview; extend `POLICY` in [redact.js](redact.js) for your app. No persistent “disable redaction” setting exists.
- Filters affect visibility, not collection or retention quotas. Fetch/XHR is the default. Filters and inspector state last only for the DevTools session. The inspector uses the same redaction path as Markdown but can show up to the full retained body; its JSON tree renders at most about 400 nodes / 8 levels, with Text view available for the remaining safe content.
